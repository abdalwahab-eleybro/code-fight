 n = len(nums)
 for i in range(n):
 for j in range(i + 1, n):
 for k in range(j + 1, n):

 Same Direction Read & Write
Pattern 2
A reader scanning ahead, a writer building behind
 Both pointers start at the beginning. The read pointer scans every element; the write pointer builds the valid result in-place.

 Cross-Cutting Technique
Guarded Skipping
Not a pattern — a rule that lives inside other patterns
 Guarded skipping is the safety detail inside a converging loop. It appears in Pattern 1 (3Sum) and in any pattern that must skip invalid or duplicate elements (Valid Palindrome).
🔒 The Rule
while left < right and skip_condition:
Every inner skipping loop 
must
 repeat the outer bound test. Without 
left < right
, the inner loop can run past valid indices and raise 
IndexError
, or silently loop forever when the outer pointers have already met.
Example G.1

 Foundations · The Seventh Primitive
Primitive 7
Introduced here because Sliding Window depends on it
 The first 6 primitives cover per-element mechanics. Sliding Window needs a 
state that spans a contiguous range
 — a sum, a set, a frequency map — updated symmetrically as the range changes.
07
Window State Expand / Shrink
O(N) aggregate · O(1)–O(k) space
Symmetric Pair:
 Every element added on expand must be removable by the same rule on shrink.
Expand (driven by 
right
):
window_sum += nums[right]
 or 
seen.add(nums[right])
.
Shrink (driven by 
left
):
window_sum -= nums[left]
 or 
seen.remove(nums[left])
, then 
left += 1
.
The Invariant:
 At the top of each outer iteration, the window state reflects exactly 
nums[left..right]
.
Guard the Shrink:
while left <= right and invalid_condition:
 — same discipline as Primitive 6.
Fixed vs Variable:
 Fixed-size shrinks exactly once per iteration; variable-size shrinks as many times as needed.

 Foundations · The Eighth Primitive
Primitive 8
Introduced here because Prefix Sum depends on it
 Every primitive so far works on 
the current element
. Prefix Sum needs something different: a 
precomputed array
 whose values are cumulative sums, so that range queries answer in O(1) instead of O(k). This is the first primitive that builds a data structure, not a pointer.
08
Cumulative State Construction (Prefix Sum / Product)
O(N) build · O(1) query · O(N) space
Prefix Array Build:
prefix[i] = prefix[i-1] + nums[i-1]
, with a leading 
prefix[0] = 0
. The extra leading slot eliminates all "what if left == 0" edge cases.
Range Sum Query:
range_sum(l, r) = prefix[r+1] - prefix[l]
 — O(1) regardless of window size.
Prefix Products:
 Same shape with multiplicative identity 
1
 instead of 
0
. Breaks if the array contains a 0 (you cannot divide by it), which is why Example 6.3 avoids division entirely. Often paired with a mirrored 
suffix
 array to answer "everything except index i" queries.
Prefix + Suffix Pairs:
 Build both arrays in one pass each; the answer at index 
i
 combines 
prefix[i]
 and 
suffix[i+1]
.
The Invariant:
prefix[i]
 equals the sum (or product) of 
nums[0..i-1]
. Never includes index 
i
 itself.
What it does NOT do:
 Prefix sum only works when the operation is 
invertible
 (sum, XOR; product only while no element is 0). It does not handle min/max queries — those need a monotonic deque (Volume 3) or a sparse table / segment tree (Volume 4). If the array changes between queries, use a Fenwick tree (Volume 4).

 window = s[i:j + 1]
# replacements needed = window size - count of its most common letter
 if len(window) - max(Counter(window).values()) <= k:
 best = max(best, len(window))
 return best
 Optimal — Window That Needs ≤ k Edits · O(N) time · O(1) space
def characterReplacement(s: str, k: int) -> int:
# Primitive 1 + 5: window start, letter counts, best frequency seen so far
 counts = {}
 left = 0
 max_freq = 0
 best = 0
# Primitive 2: right pointer expands the window
 for right, ch in enumerate(s):
 counts[ch] = counts.get(ch, 0) + 1
 max_freq = max(max_freq, counts[ch])
# Primitive 7: shrink while the replacements needed exceed k
# replacements needed = window size - most frequent letter
 while (right - left + 1) - max_freq > k:
 counts[s[left]] -= 1
 left += 1
 best = max(best, right - left + 1)
 return best
The stale-max trick:
max_freq
 is never lowered when the window shrinks. That is safe, because the answer only grows when a 
new, higher
 frequency appears, so an outdated value can never produce a wrongly large window.

(a) Longest substring with

 Optimal — Window + Frequency Map · O(N) time · O(k) space
def longestAtMostKDistinct(s: str, k: int) -> int:
 counts = {}
 left = 0
 best = 0
 for right, ch in enumerate(s):
 counts[ch] = counts.get(ch, 0) + 1
# Primitive 7: shrink until at most k distinct letters remain
 while len(counts) > k:
 counts[s[left]] -= 1
 if counts[s[left]] == 0:
 del counts[s[left]] 
# so len(counts) is the distinct count
 left += 1
 best = max(best, right - left + 1)
 return best
def count_at_most(nums: list[int], k: int) -> int:
 counts = {}
 left = 0
 total = 0
 for right, x in enumerate(nums):
 counts[x] = counts.get(x, 0) + 1
 while len(counts) > k:
 counts[nums[left]] -= 1
 if counts[nums[left]] == 0:
 del counts[nums[left]]
 left += 1
 total += right - left + 1 
# all valid subarrays ENDING at right
 return total
def subarraysWithKDistinct(nums: list[int], k: int) -> int:
# "Exactly k" is not window-friendly, but "at most k" is:
 return count_at_most(nums, k) - count_at_most(nums, k - 1)
The trick:
exactly(k) = atMost(k) − atMost(k − 1)

def removeDuplicates_brute_force(nums: list[int], k: int = 2) -> int:
 seen = {}
 kept = []
 for x in nums:

 Optimal — Read & Write with a k-Back Check · O(N) time · O(1) space
def removeDuplicates(nums: list[int], k: int = 2) -> int:
# Primitive 1: write pointer
 write = 0
# Primitive 2 & 4: read pointer scans every index

# The first k elements are always kept. After that, compare with the

 if write < k or nums[read] != nums[write - k]:
# Primitive 4: in-place overwrite at the write pointer
 nums[write] = nums[read]
 write += 1
 return write

Example X.8
Subarray Sum Equals K
LeetCode 560
Count the contiguous subarrays whose sum equals 
k
. The array 
may contain negative numbers
.
 Brute Force — Every Subarray · O(N²) time · O(1) space
def subarraySum_brute_force(nums: list[int], k: int) -> int:
 count = 0
 for i in range(len(nums)):
 total = 0
 for j in range(i, len(nums)):
 total += nums[j]
 if total == k:
 count += 1
 return count
 Optimal — Prefix Sum + Hash Map · O(N) time · O(N) space
def subarraySum(nums: list[int], k: int) -> int:
# Primitive 8: running prefix sum; seen[p] = how many earlier prefixes equal p
 seen = {0: 1} 
# the empty prefix
 running = 0
 count = 0
 for x in nums:
 running += x
# A subarray ending here sums to k <=> an earlier prefix equals running - k
 count += seen.get(running - k, 0)
 seen[running] = seen.get(running, 0) + 1
 return count
Why not a sliding window?
 With negatives, growing the window can 
lower
 the sum, so “shrink when too big” is no longer valid. 
The prefix trick:
sum(i..j) = prefix[j+1] − prefix[i] = k
, so look for earlier prefixes equal to 
running − k
. (Hash tables are formalized in Volume 3, Hash Lookup; this is a preview.)

 Debugging
7 Critical Bugs
And how to prevent them
1
Off-by-One Boundary Errors
Always initialize 
right = len(nums) - 1
. Writing 
right = len(nums)
 causes an 
IndexError
 on the first iteration.
2
Unbounded Skipping Loops
Inner skipping loops 
must
 prepend 
left < right
. Otherwise pointers run past valid indices and either crash or loop forever.
3
Overwriting Before Reading
In Read-Write patterns, always evaluate 
nums[read]
before
 executing 
nums[write] = nums[read]
.
4
Modifying Array Size Inside For Loops
Avoid 
nums.pop()
 or 
del nums[i]
 during iteration. Use Read-Write pointers to overwrite in place and return a virtual length.
5
Forgetting to Remove From Window State on Shrink
Sliding-window bugs come from a window state that drifts out of sync with 
[left, right]
. Every element added on expand must be removed on shrink. 
Primitive 7's symmetric add/remove pair is the fix.
6
Prefix Array Missing the Leading Zero
Build 
prefix = [0] * (n + 1)
, not 
[0] * n
. Without the leading 
prefix[0] = 0
, the query 
sumRange(0, r)
 has no clean left boundary and you'll special-case every 
left == 0
 call. The extra slot eliminates the entire class of edge-case bugs.
7
Kadane Initialized to 0 Instead of nums[0]
On an all-negative array, initializing 
best = 0
 returns 0 instead of the largest (least negative) element. Initialize both 
best
 and 
here
 to 
nums[0]
. For the product variant, also track 
min_ending_here
 — a negative times a negative can become the new maximum.
